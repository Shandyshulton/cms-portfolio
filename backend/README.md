## About Laravel

Laravel is a web application framework with expressive, elegant syntax. We believe development must be an enjoyable and creative experience to be truly fulfilling. Laravel takes the pain out of development by easing common tasks used in many web projects, such as:

- [Simple, fast routing engine](https://laravel.com/docs/routing).
- [Powerful dependency injection container](https://laravel.com/docs/container).
- Multiple back-ends for [session](https://laravel.com/docs/session) and [cache](https://laravel.com/docs/cache) storage.
- Expressive, intuitive [database ORM](https://laravel.com/docs/eloquent).
- Database agnostic [schema migrations](https://laravel.com/docs/migrations).
- [Robust background job processing](https://laravel.com/docs/queues).
- [Real-time event broadcasting](https://laravel.com/docs/broadcasting).

Laravel is accessible, powerful, and provides tools required for large, robust applications.

## Data Encryption (PII)

Sensitive data is protected at two layers:

**1. At rest (database)**
- `contact_submissions`: `name`, `email`, `subject`, `message`, `ip_address`, `user_agent` are encrypted with Laravel's `encrypted` cast (AES-256-CBC, keyed by `APP_KEY`).
- `settings` JSON: `general/profile.email`, `general/profile.phone`, `contact/form.recipient_email` are encrypted via `Setting` mutators/accessors (same `APP_KEY`).
- Plaintext is never stored for these fields; the model accessors decrypt transparently for internal use (mail, Web3Forms, admin read).

**2. In transit (API payload)**
- The backend wraps PII fields in `{ "data": "<base64>" }` objects using AES-256-GCM with the `PAYLOAD_ENCRYPTION_KEY` (see `.env`).
- The admin frontend fetches this key from `GET /api/admin/encryption-key` (auth required), keeps it in memory, and decrypts/encrypts transparently in `admin/src/lib/payloadCrypto.js` + `api.js`.
- Format: `base64(iv(12) + ciphertext + tag(16))`.

**Public API** (`GET /api/public/settings`) strips PII fields entirely — email, phone, and recipient email are never exposed to unauthenticated clients.

### Notes
- `PAYLOAD_ENCRYPTION_KEY` must be a base64-encoded 32-byte value. Generate with:
  ```bash
  php -r "echo base64_encode(random_bytes(32)), PHP_EOL;"
  ```
- If `APP_KEY` is rotated, at-rest data can no longer be decrypted. Keep `APP_KEY` stable.
- Migration `encrypt_existing_pii_data` converts legacy plaintext rows to encrypted form; `migrate:rollback` restores them.
